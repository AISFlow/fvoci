# Fixture provenance

`sample.pdf` and `sample.docx` are generated by `gen.py` from public container specs.
`sample.hwp` and `sample.hwpx` were replaced in commit `bea3243` by the project
owner, who confirmed on 2026-09-24 that they authored the word `안녕` while checking
the files and authorized continuing with them. Both were saved by Hancom Office
Hangul 12.30.0.6446; the HWPX section text is `안녕`. These are test documents,
not customer uploads. Embedded creator metadata is `kinesis`.

The HWP includes BodyText/Section0, preview data and default Hancom script
streams. Parsers must not execute embedded scripts. Font names are references,
not bundled font programs. Presence of BodyText is not proof of successful
extraction; the old compatibility probe has no HWP body decoder.

`gen.py --output-dir <empty-directory>` creates separate synthetic specimens.
It refuses the checked-in fixture directory and nonempty directories so it
cannot silently replace the authored HWP/HWPX samples.

Inspected locally (not copied into this tree) from the private source checkout
at SHA `393795261322b916e588043cf94feca999175843`:

- `apps/web/src/features/attachments/fixtures/PROVENANCE.md`
- `sample.pdf` — authored PDF 1.4, Storybook/pdf.js, text `FVOCI PDF`

- `sample.hwpx` — in-repo HwpViewer sample (ZIP: mimetype, version.xml,
  META-INF/container.xml, Contents/content.hpf, header.xml, section0.xml)
- No checked-in `.hwp`; tests build a CFB (HWP 5.0) fixture in-process

Source extract/thumbnail paths (read-only, not reimplemented):

- Text: `packages/jobs/src/extract-text.ts` — `pickExtractor`:
  `.hwp`/`.hwpx` → `hwpx-js`; pdf/docx/pptx/xlsx/odt/… → `officeparser`

  raster MIME only (`image/png|jpeg|gif|tiff|bmp|webp|apng`) via magick-wasm.
  PDF/DOCX/HWP/HWPX are not in that preview set.
