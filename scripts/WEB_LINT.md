# Web lint and formatting

Use `bun ci` with the root workspace's Bun 1.4.2 lockfile. Run `bun run lint`,
`bun run format:check`, and `bun run lint:fixtures`. The scripts execute the
installed CLI with `bun --bun` and validate exact package versions; they never
download a tool at invocation time. There is no global CLI or Node requirement.

The root flat config combines ESLint JS recommended, typescript-eslint
strictTypeChecked, and Vue flat recommended. `vue-eslint-parser` parses full
SFCs with the TypeScript parser for scripts. Minimal `tsconfig.eslint.json`
projects extend the existing strict projects and include source, tests, and
configuration. They do not replace the existing tsc/vue-tsc typechecks.
Before lint runs, `prepare-vue-lint-types.mjs` uses pinned vue-tsc to emit
disposable declarations for the editor SFC project and the web `App.vue`
import boundary. The web declaration project follows App's dependencies rather
than emitting every route's declarations. Keep its roots aligned with direct
SFC imports that need component types in plain TypeScript consumers; lazy route
components remain checked by the full web vue-tsc project.
Both lint projects resolve this generated layer through `rootDirs`; there is
no ambient SFC shim or hand-written component declaration. Generation clears
the whole cache first and removes all output if either project fails, so stale
or partially refreshed types cannot let a failed source check pass lint.
Template type errors, unknown components, typed props, emits, and slots remain
the responsibility of vue-tsc; template syntax and directives are checked by
the Vue plugin. Nuxt UI component/composable autoimports are disabled in FVOCI,
so fixtures use an actual installed component import and reject an unregistered
component through vue-tsc.

Warnings fail (`--max-warnings=0`), unused suppression directives are errors,
and floating promises cannot be dismissed with `void`. Browser, Worker, build
tools, and Bun tests have separate globals. Browser source rejects runtime
Node/Bun globals even when ambient dependency types declare them. There are
no existing-violation baselines, per-file rule exceptions, or ignored Vue files.

Prettier is the sole formatter. eslint-config-prettier is last and disables
conflicting style rules only. No formatter plugin, import sorting, or autofix
runs in CI. Sensitive HTML whitespace uses `strict`; proofs retain inline text,
preformatted whitespace, side-effect import order, scoped deep/slotted CSS,
and Tailwind directives. Later whole-scope formatting requires its own review.

The default scope is all maintained apps/web, packages/editor, packages/i18n,
their sources/tests/configuration, and frontend development scripts. ESLint
handles JS/TS/TSX/Vue; Prettier additionally handles JSON/JSONC, CSS, HTML, and
Markdown. Neither provides semantic CSS, JSON, or Markdown linting. The existing
strict compilers supply template type checking; no additional linter is added.

Generated API source/OpenAPI output are verified by generate-api.sh and are
excluded from formatting; generated API source is also excluded from lint.
Locks belong to the package manager. Copied NOTICE/font license text is excluded
from formatting to retain attribution verbatim. Dependencies and local CodeGraph
state are excluded. External vendored code and immutable compatibility oracle
bytes are outside the maintained frontend scope; the root config also protects
these if a caller passes a wider path. Hand-authored test fixtures are included.

`web-static` installs locked dependencies and runs the checks once without
Rust/DB prerequisites. Its selector is generated by the same fail-closed planner
as other Web jobs and its result is required by web-ci-gate. Browser shards do
not repeat lint, formatting, or typechecking.

`bun run lint:fixtures` runs the Bun test `scripts/eslint-fixtures.test.ts`. It
exercises the installed parsers/plugins/typed rules, Prettier, tsc/vue-tsc, and
both positive/negative fixture proofs. Child tools run from the running Bun
binary. The harness captures regular-file stdout
because Bun 1.4.2 can truncate ESLint's large print-config output when piped.
Full diagnostics should likewise use
`bun run lint --format=json --output-file=/tmp/web-eslint.json`.
The declaration fixtures cover the actual web/editor imports, generated prop
types, genuine unsafe props, and a failed second project clearing both earlier
and stale emissions. Run one of those proofs alone from the repository root with
`bun test --timeout=600000 ./scripts/eslint-fixtures.test.ts -t "<test name>"`,
for example `actual_web_and_editor_declaration_preparation_is_node_free`,
`multiple_declaration_projects_fail_closed_together`,
`generated_sfc_types_and_failed_refresh_have_no_waiver`, or
`unprepared_sfc_import_has_no_fake_fallback`.

This setup is Phase A. Existing source diagnostics must be fixed in separate
mechanical formatting, rule/import, and behavior commits with independent
review before overall lint acceptance. No product source was modified here.
