# `src/lib`의 층

`src/lib` 바로 아래의 첫 폴더(또는 파일)가 **층**이다. 층은 아래에서 위로 쌓이고, 파일은 **자기 층과 자기보다 낮은 층**에서만 가져온다. ESLint 규칙 `fvoci/layer-order`(`tools/lint/layers.ts`의 `LAYERS` 표)가 검사하고 `check`에 들어 있다. 표에 없는 폴더를 만들면 규칙이 실패하므로, 새 층은 그 표와 이 문서에 함께 적는다.

| 높이 | 층                                                                                                      | 무엇                                                                                                                                                      | 가져올 수 있는 것                   |
| ---- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| 0    | `logic/`                                                                                                | 순수 로직. DOM, 기기의 시간대, 번역을 모른다                                                                                                              | 자기 층                             |
| 0    | `i18n/`, `hooks/`, `utils.ts`, `keys.ts`, `focus.ts`, `theme.svelte.ts`, `fragment-token.ts`, `save.ts` | 메시지(생성물), 생성 UI의 보조, 기기의 단축키, 포커스 옮기기·되돌리기, 밝은·어두운 화면의 클래스, 일회성 조각·초대 토큰 보관·제거, 바이트를 이름으로 저장 | 자기 층                             |
| 1    | `regional.ts`, `display.svelte.ts`, `chunk-reload.svelte.ts`                                            | 표시 설정의 지금 값(시간대·주의 시작·시간 표기, 화면 밝기·카드 여는 방식·밀도·진동), 지연 청크·구버전 감지 및 기준 경로 읽기                              | 높이 0                              |
| 1    | `layout/`                                                                                               | 화면 크기의 세 단계, 경계 값, 안전 영역, 뒤로 가기로 닫는 층                                                                                              | 높이 0                              |
| 1    | `drag/`, `editor/`, `file-viewer/`, `fonts.ts`                                                          | 드래그의 기반, 본문 문서(허용 목록, 표시기, 편집기 확장), 파일 보기(형식 가리기, 틀과의 메시지; 틀은 `src/viewer-frame/`), 글꼴 규칙의 지연 로드          | 높이 0                              |
| 2    | `state/`                                                                                                | **데이터의 경계.** 화면이 쓰는 읽기·쓰기·구독의 인터페이스, 메모리 구현(`state/memory/`), 실행 취소와 낙관적 갱신                                         | 높이 0–1                            |
| 2    | `ui/`                                                                                                   | shadcn-svelte CLI가 만든 부품(그 폴더의 README)                                                                                                           | 높이 0–1                            |
| 3    | `components/`                                                                                           | 손으로 쓴 공용 부품. 여러 화면이 함께 쓴다(속성 편집기 `components/properties/` 포함)                                                                     | 높이 0–2. **단 `state/`는 안 된다** |
| 3    | `api/`                                                                                                  | **서버를 부르는 구현.** 데이터의 경계(`state/backend.ts`)를 서버의 API로 채운다. 타입은 계약에서 만든다(`contract.ts`)                                    | 높이 0–2                            |
| 4    | `features/<기능>/`                                                                                      | 화면. 기능끼리는 서로 가져오지 못한다(`fvoci/feature-boundaries`, 그 폴더의 README)                                                                       | 모든 층. 다른 기능은 안 된다        |
| —    | `src/app/`                                                                                              | 진입점, 라우터, 기능의 조립. 어느 것이든 가져온다                                                                                                         | 전부                                |

두 가지 예외 규칙:

- **공용 부품(`components/`)은 `state/`에서 가져오지 않는다.** 값과 콜백을 인자로 받는다. 그래야 Storybook과 테스트에서 저장소 없이 그릴 수 있다. 상태를 읽어 부품에 넘기는 일은 기능(`features/`)이 한다.
- **화면은 서버를 직접 부르지 않는다**(`fvoci/no-direct-server`). `src/` 아래에서 `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `sendBeacon`을 쓰거나 경계의 구현(`state/memory/`, 장차의 `api/`)을 가져오면 실패한다. 예외는 구현 자신(`state/`, `api/`)과, 어느 구현을 꽂을지 정하는 한 파일 `src/app/backend.ts`뿐이다.

## 무엇을 어디에 두나

- 두 기능이 같이 쓰게 된 것은 풀지 말고 **내린다**: 계산은 `logic/`, 데이터는 `state/`, 화면 부품은 `components/`. 기능 폴더끼리 가져오지 못하는 규칙을 끄지 않는다.
- 속성 편집기는 칸반 카드, 테이블 칸, 카드 상세, 갤러리가 함께 써서 `components/properties/`에 있다(2026-11-10에 `features/properties`에서 옮겼다).
- 생성 UI(`ui/`)를 손대면 그 폴더의 README 표에 적는다. 직접 쓴 부품을 거기에 두지 않는다.
