# Candidate migration

Keep the current `.sh` launchers and waiter unchanged until independent forward review and controller approval. Their presence remains part of the external run memory, not part of this skill. This package supplies candidate behavior and isolated tests; it does not claim the running chain has migrated.

Read the current chain's original worker, review and wait entrypoints against the controller's verified inventory, without modifying them. Retain their meaningful argv, common-plus-unit prompt, Task spec and report contracts. Do not inherit a historical Run snapshot, omitted parent, fixed pauses or first-terminal selection. Compare current installed CLI guides/help and supported provider launcher options before choosing a route; a profile or a historical provider-specific entrypoint is not evidence that a bundled adapter supports that provider. The bundled execution adapters are `codex` and `claude`, selected explicitly per profile role.

After review, the controller can replace the bodies of its existing author/reviewer entrypoints with an `exec` invocation of `bun <installed-skill>/scripts/legacy.ts worker "$@"` or `bun <installed-skill>/scripts/legacy.ts review "$@"`, respectively. Preserve their current argument interfaces through this Bun caller; do not interpolate those arguments into shell JSON, copy the old run snapshot, fetch/reset a checkout, or select the first terminal. Author and reviewer common prompts remain external. Explicitly select an existing terminal only after Orca reuse is authorized. A review-model exception is a `reviewer` profile entry on a bundled adapter. Providers outside the bundled adapters need their own reviewed adapter.

The old waiter entrypoint can invoke `bun <installed-skill>/scripts/legacy.ts wait "$@"` once, after the controller has positively confirmed that the previous waiter ended and its final delivery was handled. Consume the complete receipt with controller decisions, then call `process --decisions <private-decisions>`. Process any returned ack batch before starting another wait. The old automatic heartbeat-only ack loop is removed: heartbeat/status messages also require full-batch handling. Do not kill a currently blocked wait or introduce a second wait during migration.

Before switching, complete the checks in [validation.md](validation.md) on a copied package from another cwd, then inspect against the actual local locator. Keep adapter/model/effort/tier, explicit parent, heavy-command resource limits and external state authority verified. Stub success does not authorize a live launch test. After a `claude` launch, run `confirm` for its Dispatch before claiming the model that actually answered. Forward review is assigned by the controller, and live worker launch/wait/settlement remain untested until separately authorized.

For a fresh installation, copy this package directory to the user skill directory without copying a current locator or execution memory into the repository. Create the private external locator from current verified receipts and user model choices, then inspect it from another cwd. Repository source and user installation must be byte-identical at review. The existing shell files are not installed or replaced by this package; review the controller-provided exact patch separately. Apply that patch only after the old waiter has positively ended and its final delivery and any ack-returned batch have been processed. Preserve an active waiter and defer switching if that proof is missing; local guards cannot discover an older waiter that never used them. Use a fresh output path for every single wait, and never remove a failed guard just to continue.
