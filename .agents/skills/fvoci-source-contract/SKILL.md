# 프론트·API·협업의 원본 계약 조사

공통 모델·권한·소유권 규칙은 루트 AGENTS.md를 따른다. 이 스킬은 원본을 읽기 전용 근거로 사용한다.

## 입력

원본 기본 브랜치/PR의 고정 SHA, task의 목표와 허용 경로, 관련 UI 호출 또는 API/저장 데이터 경계.

## 절차

1. 해당 UI 호출/라우트에서 제품 연산·영속화·대표 테스트로 실제 호출 경로를 좁게 추적한다. 문서·PR 설명과 실제 구현의 차이를 구분한다.
2. URL/상태 코드/오류, JSON 누락·null, ID/날짜/커서, 인증·인가, 저장 데이터의 의미를 추출한다. 알려진 결함은 보존 대상으로 간주하지 않는다.
   고정 SHA는 비교 재현성의 기준이다. 실제 사용자 흐름·소비자 의존성을 확인하고 언어별 우연한 출력이나
   원본 보정 분기를 제품 계약으로 자동 승격하지 않는다. 차이는 회귀·실제 호환성 문제·결함 수정·의미가 같은 표현으로 구분한다.
3. 성공 외에 권한 철회·정지, 중복 요청·응답 유실, 외부 실패·rollback, 재접속·복구의 필요한 수락 조건을 정한다.
4. 협업은 정확한 클라이언트/프로토콜/저장 형식을 확인하고 실제 두 클라이언트·한글/이모지·재접속·권한 철회·복원을 좁게 재현한다. 라이브러리 호환 주장을 FVOCI 검증과 구분한다.
5. 같은 조사를 모든 워커가 반복하지 않게, 구현에 필요한 계약과 테스트 근거만 담당 워커에게 전달한다. 전체 코드나 채팅을 복제하지 않는다.

## 결과

고정 SHA와 파일/함수, 보존할 계약, 기존 결함·미완료, 새 구현의 수락 시나리오, 실행한 재현과 미실행 범위를 반환한다. 기능 대응표 갱신은 코디네이터에게 전달한다. 문서만으로 실제 지원을 확정하지 않는다.
