## CJK typography and scaling

Use rem-based semantic typography tokens. Consistency means shared sizes and unitless line heights for the same content role, not one size for every element. Map Nuxt UI/Tailwind variants to those roles; avoid scattered pixel font sizes and conflicting utility overrides. Do not mechanically convert borders, icons, canvas/document coordinates, attachment/export sizes, or every pixel dimension to rem.

For the next approved UI implementation, start with 1rem and approximately 1.6 line-height for reading/body and primary form text; use 0.875rem and approximately 1.5 line-height for short labels, menus, and deliberately dense table/control text. Retain 1.5rem titles unless actual wrapping calls for adjustment. These are FVOCI design starting points to validate with real Korean content, not WCAG-mandated minimum sizes. Do not default essential instructions, errors, field labels, or primary data to 0.75rem. Reserve smaller captions for genuinely secondary metadata and justify density exceptions with actual visual evidence.

The current implementation already has rem tokens in `apps/web/src/styles/tokens.css`, while `apps/web/src/lib/ui-preferences.ts` writes a persisted 16/18/20px root scale. Do not claim this documentation changes those values. When implementing browser-relative root sizing, prefer an unshrunk 100% default and reconcile the existing textScale preference and its tests before changing the JavaScript override. Preserve user scaling choices; do not silently reset them or use a smaller root to make rem values appear larger.

Verify the editor's computed document font size and the definition of any semantic variable it consumes, including `--text-doc`; a CSS declaration alone is not evidence that the intended size is effective. Preserve unitless leading and Korean word-boundary wrapping with an emergency break for long URLs/identifiers. Inspect mixed-script and supported CJK text in actual fonts. Allow controls, rows, menus and error messages to grow rather than clip enlarged text.

For typography implementation and acceptance, check the default and larger app text settings, browser-default font changes, 200% text enlargement, 320 CSS px reflow, and user text-spacing overrides. Use real screenshots and keyboard flows across shell/list, forms/settings, editor, calendar and dialogs. Necessary two-dimensional tables/canvases may scroll within their region; surrounding labels, search and navigation still need to reflow. Do not treat rem usage alone as readability or accessibility acceptance.

Reference criteria: [Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html), [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html), and [relative font sizing](https://www.w3.org/WAI/WCAG22/Techniques/css/C14). Text-spacing resilience does not require authored defaults to equal all override values. This brief defines implementation/review guidance; it does not report product changes, browser testing, or compliance certification.
